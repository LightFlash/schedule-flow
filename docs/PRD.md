## 一、项目信息

- **Language（文档语言）**：中文
- **Programming Language（技术栈）**：Electron + React（用户指定）；构建工具与 UI 组件库由架构师决定，UI 需为现代风格
- **Project Name**：`schedule_flow`
- **交付形态**：Windows 可执行文件（exe，可双击运行）+ 完整源码

### 原始需求复述

用户需要一款「个人日程 + 工作汇总」桌面工具，包含三大核心能力：

1. **番茄时钟**：可自定义轮次数量、工作/休息时长间隔；到时间时强提醒——窗口全局置顶 + 微信消息推送。
2. **TODO List**：记录待办工作，工作结束后标记完成并记录，每项工作有备注/心得区域，支持按天/周/月/年汇总。
3. **工作计时**：每项工作开始时可手动或自动开始计时（分钟级），结束可停止并与 TODO 联动，计时期间可暂停/继续，每项工作独立计时，汇总每项工作的累计用时。

微信提醒方式：Server酱 / PushPlus 推送，用户自行在设置中填入 SendKey / Token。

## 二、产品定义

### 2.1 产品目标（Product Goals）

1. **专注执行**：通过可配置的番茄钟与「窗口置顶 + 微信推送」的强提醒机制，帮助用户保持专注、按节奏工作与休息，避免超时与错过节点。
2. **工作留痕**：通过 TODO 清单 + 每项工作独立计时 + 备注/心得，完整记录每项工作的投入过程与复盘信息。
3. **可度量复盘**：通过按天/周/月/年的多粒度汇总，把完成任务数与时间投入可视化，帮助用户评估时间分配与效率。

### 2.2 用户故事（User Stories）

1. 作为**专注工作的个人用户**，我想设置番茄钟的工作/休息时长与轮次，并在到点时得到窗口置顶和微信推送的强提醒，以便我不用一直盯着时间也不会错过休息。
2. 作为**待办事项较多的知识工作者**，我想记录待办工作、完成后标记完成并写下备注/心得，以便日后复盘每项工作的过程与收获。
3. 作为**需要精确统计时间投入的用户**，我想为每项工作单独开始/暂停/继续/停止计时，并自动累加用时，以便准确掌握每项工作花了多少时间。
4. 作为**希望复盘时间分配的用户**，我想按天/周/月/年查看完成数量与累计用时汇总，以便了解自己在各周期的时间投入趋势。
5. 作为**经常离开电脑的用户**，我想在设置里填入 SendKey/Token 并接收微信推送提醒，以便即使不在电脑前也能收到番茄钟到点通知。

## 三、技术规范

### 3.1 需求池（Requirements Pool）

> 优先级定义：**P0 = 必须（首版交付）**，**P1 = 应该（后续迭代）**，**P2 = 可以（锦上添花）**。
> 首版（v1.0）交付范围 = 全部 P0 项，须可打包为 Windows exe 并双击运行。

#### P0 — 必须（首版交付）

**A. 应用骨架与交付**

- P0-A1：应用须基于 Electron + React 构建，可运行于 Windows，并可打包为可双击运行的 exe。
- P0-A2：应用启动后默认展示主窗口，提供左侧导航与四个主视图（番茄钟、TODO、工作计时、汇总）。
- P0-A3：应用数据须全部本地持久化，不依赖网络即可查看历史数据（推送提醒除外）。

**B. 番茄时钟**

- P0-B1：用户可自定义「工作时长」「休息时长」（单位：分钟）与「轮次数量」。
- P0-B2：提供开始、暂停、继续、重置操作；界面实时显示当前剩余时间与当前所处阶段（工作 / 休息）。
- P0-B3：按设定轮次自动在工作与休息阶段间切换（如：工作 N 分钟 → 休息 M 分钟 = 1 轮，完成设定轮次后结束）。
- P0-B4：**强提醒**——当工作/休息阶段结束时，须同时触发：① 主窗口全局置顶（alwaysOnTop）并闪烁/高亮提醒；② 微信消息推送提醒。提醒须持续到用户手动确认（关闭提醒）为止。
- P0-B5：番茄钟运行期间，其余视图仍可正常操作（番茄钟在后台继续计时）。

**C. TODO List**

- P0-C1：支持新建、编辑、删除待办工作项。
- P0-C2：每项工作可标记「完成 / 未完成」，并记录完成时间。
- P0-C3：每项工作提供备注/心得输入区，可随时编辑并保存。
- P0-C4：每项工作展示其关联累计用时（来自工作计时，见 D 组）。
- P0-C5：工作项数据须本地持久化。

**D. 工作计时**

- P0-D1：每项工作拥有**独立计时器**与**独立累计用时**，互不干扰。
- P0-D2：支持为选中的工作「开始计时 / 停止计时」，计时精度到分钟级（界面可显示到秒，累计以分钟计）。
- P0-D3：计时期间支持「暂停 / 继续」，暂停时间不计入累计用时。
- P0-D4：停止计时时，将本次计时时长累加到对应工作项的累计用时中，并与 TODO 状态联动（工作项可被标记为完成）。
- P0-D5：同一时刻只允许一项工作处于计时中；切换计时对象时须先停止当前项（默认决策，见 3.3）。
- P0-D6：应用关闭/崩溃后，进行中的计时不得丢失（记录开始时间戳，重启后按真实经过时间恢复）。

**E. 汇总统计**

- P0-E1：支持按 **天 / 周 / 月 / 年** 四种时间粒度切换查看汇总。
- P0-E2：汇总内容须包含：各周期内「完成任务数」与「累计工作用时」；每项工作的累计用时明细。
- P0-E3：汇总口径默认决策见 3.3。

**F. 设置与推送**

- P0-F1：提供「设置」弹窗，作为微信推送配置入口。
- P0-F2：用户可在设置中选择推送渠道（Server酱 / PushPlus），并填入对应的 SendKey / Token；配置须本地持久化。
- P0-F3：提供「测试推送」按钮，用于验证配置是否生效。
- P0-F4：未配置推送凭证时，强提醒仅执行窗口置顶/高亮，不发送微信推送，且给出友好提示。

#### P1 — 应该（后续迭代）

- P1-1：番茄钟与工作计时联动——番茄钟「工作阶段」开始时，自动为当前选中的 TODO 项启动计时（默认决策见 3.3）。
- P1-2：长休息机制——每完成 N 轮后进入一次较长时间休息，长短休息时长可分别配置。
- P1-3：提醒自定义——提醒声音、置顶闪烁样式可选。
- P1-4：TODO 增强——支持优先级、标签/分类、按状态筛选与搜索。
- P1-5：数据导出——支持导出 JSON / CSV 便于备份与外部分析。
- P1-6：系统托盘支持——最小化到托盘、托盘快捷操作。

#### P2 — 可以（锦上添花）

- P2-1：深色/浅色主题切换。
- P2-2：汇总视图增加可视化图表（趋势折线图、时间分布环形图）。
- P2-3：开机自启、全局快捷键（开始/暂停番茄钟）。
- P2-4：推送历史记录与提醒日志。

### 3.2 UI 设计稿（文字 + 结构化描述）

**整体框架**：现代风格桌面应用，浅色基调、圆角卡片、柔和阴影，左侧固定导航 + 右侧内容主区。顶部为标题栏（窗口控制）。

```
+---------------------------------------------------------------+
|  标题栏  [Schedule Flow]                        [—][□][×]      |
+----------+----------------------------------------------------+
|          |  主内容区                                           |
| 左侧导航 |                                                    |
|          |  （随选中视图切换，见下方各视图说明）               |
|  🍅 番茄钟|                                                    |
|  ✓ TODO  |                                                    |
|  ⏱ 计时  |                                                    |
|  📊 汇总  |                                                    |
|          |                                                    |
|          |                                                    |
+----------+----------------------------------------------------+
|          |                                        ⚙ 设置      |
+----------+----------------------------------------------------+
```

**1）番茄钟视图**

- 中央大号倒计时圆环/数字（剩余时间），环上显示进度。
- 圆环下方：当前阶段标签（工作中 / 休息中）与轮次进度（如 `第 2 / 4 轮`，用小圆点表示已完成轮次）。
- 主操作按钮：开始 / 暂停 / 继续 / 重置（按状态切换显示）。
- 侧边/底部：本轮参数快捷设置（工作时长、休息时长、轮次数），点击可编辑，与设置弹窗联动。
- 顶部提示区：显示当前推送配置状态（已配置 / 未配置）。

**2）TODO 视图**

- 顶部：新建输入框（输入工作标题 + 添加按钮）。
- 列表：每项工作一行，包含勾选框（完成状态）、标题、累计用时徽标、展开按钮。
- 展开区：备注/心得多行文本框（自动保存）、编辑/删除操作、该项「开始计时」快捷按钮。
- 筛选栏（P1）：按状态/标签筛选、搜索框。

**3）工作计时视图**

- 顶部：当前计时对象选择器（下拉选择 TODO 项）+ 大号计时显示（`HH:MM:SS`，累计 + 本次）。
- 主操作按钮：开始 / 停止 / 暂停 / 继续（按状态切换显示）。
- 下方：所有工作项的计时列表（标题、累计用时、状态标识「计时中 / 已暂停 / 未开始」），可展开查看明细。

**4）汇总视图**

- 顶部：时间粒度切换标签（天 / 周 / 月 / 年）。
- 统计卡片区：当前周期内「完成任务数」「累计工作用时」「完成番茄轮次数」三个指标卡。
- 明细区：按选中粒度分组的工作明细列表（工作标题、完成时间、用时、备注摘要），支持展开查看完整心得。
- 图表区（P2）：趋势图与时间分布图占位。

**5）设置弹窗（Modal）**

- 推送配置分组：渠道单选（Server酱 / PushPlus）→ 对应 SendKey / Token 输入框（密码态）→「测试推送」按钮 + 结果提示。
- 番茄钟默认参数分组：默认工作时长、默认休息时长、默认轮次数。
- 数据管理分组（P1）：数据导出入口、数据目录位置说明。
- 底部：保存 / 取消。

### 3.3 关键设计决策与默认口径（含糊点细化）

> 以下为产品经理给出的**默认设计决策**，架构师与工程师可按此实现；如需变更请回归确认。

1. **工作计时与 TODO 的联动方式**：每个 TODO 项内置字段 `accumulatedMs`（累计用时）与 `timingStatus`（未开始 / 计时中 / 已暂停）。计时器绑定到具体工作项；「停止计时」时把本次时长累加到该项 `accumulatedMs`，并在 TODO 列表同步展示。停止计时后提供「标记为完成」的引导（可在设置中开关自动标记，默认不自动标记，由用户手动确认）。
2. **番茄钟与工作计时是否共用计时器**：默认**不共用**，二者为独立计时器，避免口径混淆。番茄钟负责固定节奏的专注循环，工作计时负责绑定具体工作的用时统计。联动关系（P1-1）：番茄钟工作阶段开始时，若用户已选中某个 TODO 项，则自动启动该项计时；未选中则仅运行番茄钟。
3. **同一时刻多项计时**：默认同一时刻只允许一项工作计时中；开始新项计时前须停止当前项（弹窗确认）。数据模型中以单一 `activeTimerId` 记录当前计时对象。
4. **汇总统计口径**：以工作的**完成时间**（标记完成的时刻）作为归档依据；未完成但有计时的工作按**最后计时时间**归档到对应周期。周期划分：天=自然日，周=自然周（周一起算），月=自然月，年=自然年。累计用时取各工作项 `accumulatedMs` 之和，统一换算为分钟展示。
5. **数据本地存储方式**：默认使用应用用户数据目录下的本地 JSON 文件持久化（结构含 `todos`、`settings`、`pomodoroRecords` 等），由架构师决定具体库（如 electron-store）。要求原子写入以避免损坏；进行中的计时额外持久化开始时间戳以支持崩溃恢复（P0-D6）。
6. **SendKey / Token 配置入口**：统一放在「设置」弹窗的推送配置分组，按渠道分别保存凭证；提供测试推送验证。凭证仅本地保存，不明文展示（输入框密码态）。
7. **强提醒触发边界**：工作阶段结束与休息阶段结束均触发提醒；到点后提醒持续（窗口置顶 + 高亮闪烁 + 微信推送），直到用户点击「确认/关闭提醒」。推送失败时不影响本地强提醒。

### 3.4 待确认问题（Open Questions）

1. **打包工具选择**：使用 electron-builder 还是 electron-forge？是否需要代码签名？（默认建议 electron-builder，首版不做签名。）
2. **推送渠道优先级**：两者是否都需首版支持？若用户同时填写两个渠道，是否都推送？（默认：首版均支持，同时填写则都推送。）
3. **是否需要多语言**：首版是否仅中文？（默认仅中文。）
4. **数据规模与备份**：是否需要历史数据自动备份/回滚？（默认首版不自动备份，P1 提供手动导出。）
5. **番茄钟结束后的行为**：完成全部轮次后是自动停止还是循环下一组？（默认自动停止并提示。）
6. **自动开始下一阶段**：工作/休息阶段结束后是否自动进入下一阶段计时？（默认自动进入，提醒需用户确认但计时继续；如需手动进入请在评审中确认。）
