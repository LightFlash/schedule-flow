## 一、原始需求复述与现状差异

**用户原话**：「任务计时可以多开，排序是新开置顶」。

| 现状（1.0.2） | 本次目标（1.0.3） |
| --- | --- |
| 全局唯一 `activeTimerId`，同一时刻只允许 1 项计时；开始另一项需先确认停止当前项 | 允许多个任务**同时**计时，各自独立开始/暂停/继续/停止，互不影响 |
| `WORK_START/PAUSE/RESUME/STOP` 命令不带目标参数（作用于唯一活动计时） | 每条命令必须带目标工作项，作用于该项 |
| 工作计时页为「选择对象 + 一个大号数字 + 暂停/停止」单计时形态 | 改为**进行中计时列表**，每条独立展示与独立控制 |
| 重启后只恢复单个计时 | 重启/崩溃后**所有**计时按真实时间恢复 |
| 开始计时已置顶（`moveTodoToTop`） | 保留，且仅对"新开始"生效 |

## 二、产品目标

**一句话**：把「工作计时」从单任务独占升级为多任务并发，让用户能一边等编译/等接口/等对方回复，一边推进另一件事，并把时间准确记到各自任务上。

关键价值：**① 不打断真实工作节奏**（等待型任务不必停止，切任务零成本）；**② 计时可见**（多条计时在顶部形成"正在做的事"区块，新开的一条立刻可见）；**③ 数据不受损**（每项累计口径不变，汇总无需理解"多开"）。

## 三、用户故事

1. 作为开发者，我同时开「修构建脚本」「写季度复盘」「等接口联调」3 个计时，希望能各自暂停继续，不需要停掉别人。
2. 作为用户，我刚点了「等接口联调」的开始，希望它立刻出现在清单最上面，一眼就能看到已经在跑。
3. 作为用户，我想逐个停止某个任务计时并结算用时，其它计时继续跑。
4. 作为用户，我关掉程序再打开（或程序崩溃过），希望所有还在跑的计时按真实经过时间继续，不能只有一个还活着。
5. 作为用户，我把某个多开中的任务勾选完成，希望只停掉它这一项，其它计时不受影响。

## 四、需求池（Requirements Pool）

### P0 — 必须

| # | 需求 | 说明 / 验收口径 |
| --- | --- | --- |
| P0-1 | **计时并发** | 每个任务独立运行态；对某项 start/pause/resume/stop 不改变任何其它项的 `timingStatus` 与累计时间。同一任务重复 start = 继续该项，不产生第二条运行态。已完成任务仍不可开始计时（沿用现状）。 |
| P0-2 | **新开计时置顶** | 状态由 `idle/paused → running` 中的"**首次开始**"时，把该项移到未完成区顶部（沿用 `moveTodoToTop`）；其余任务相对顺序不变。暂停/继续不改变顺序。 |
| P0-3 | **运行态模型改造** | 持久化运行态从「单条」改为「按工作项分组的多条」，每项保存 `status / startedAt / accumulatedBeforePauseMs / pauseStartedAt`；旧数据（单条）自动迁移为 0 或 1 条，不报错、不丢 `accumulatedMs`。具体字段形态由架构师定。 |
| P0-4 | **IPC 口径** | `WORK_PAUSE / WORK_STOP / WORK_RESUME` 增加 `todoId` 载荷（`WORK_START` 已有），三端契约测试同步更新；删除原先"请先停止当前计时"的失败分支与前端"切换计时对象"的二次确认。 |
| P0-5 | **tick 视图态** | `WorkTimerViewState` 由单活动项改为「进行中项数组」（含每项 `sessionElapsedMs`、`accumulatedMs`、`status`），250ms 广播一次；渲染层不再自行推算时长。 |
| P0-6 | **工作计时页改版** | 从"单计时器界面"改为**进行中计时列表 + 每条独立控制**；无计时时显示空态（见第五节）。保留原「工作项用时」列表（累计时间查看与删除入口）。 |
| P0-7 | **重启/崩溃恢复** | 启动时对**每条**运行态校验：`running` 按 `startedAt` 用真实时间补齐（含程序关闭期间），`paused` 用暂停前累计值；指向已删任务的运行态被丢弃，其余不受影响。 |
| P0-8 | **勾选完成 = 停该项** | `TODO_TOGGLE` 完成时只停止该项计时并结算，其它计时继续；沿用"完成后沉底 / 取消完成回未完成区末尾"。删除任务时同样只停该项。 |
| P0-9 | **并发下的停止结算** | 每项 stop 各自结算：`accumulatedMs += 本次会话时长`，写 `lastTimingAt`，`timingStatus = idle`；`autoMarkComplete` 开启时只对触发 stop 的那一项生效并沉底。 |

### P1 — 应该

| # | 需求 | 说明 |
| --- | --- | --- |
| P1-1 | 汇总口径不变 | 汇总按每项 `accumulatedMs` 统计，多开时同一天的多个任务各自计入，不做去重/合并；不因并发产生负数或跨项串味。 |
| P1-2 | 顶部汇总条 | 工作计时页顶部显示「进行中 N 项 · 本次合计 X」；N=0 时隐藏。 |
| P1-3 | 新增任务插入位置 | 现规则"插到计时任务之下"改为"插到**全部**进行中计时任务之下，保持计时区块完整"。 |
| P1-4 | 停止全部 | 列表底部提供"全部停止"，逐项结算；无计时时不显示。 |

| P2-1 | 并发数量上限 | 默认不设上限，由用户自己控制（见第六节）。 |

## 五、UI 说明

### 5.1 工作计时页（改版后）

```
┌──────────────────────────────────────────────────────────┐
│ 工作计时              ● 进行中 2 项 · 本次合计 01:12:33    │
├──────────────────────────────────────────────────────────┤
│ [ 选择工作项 ▾ ]                        [ 开始计时 ]      │
├──────────────────────────────────────────────────────────┤
│ ● 等接口联调                00:42:10     [⏸暂停] [⏹停止]  │
│   累计 03:20:00                                          │
│ ──────────────────────────────────────────────────────── │
│ ❚❚ 写季度复盘               00:30:23     [▶继续] [⏹停止]  │
│   累计 00:58:10                                          │
├──────────────────────────────────────────────────────────┤
│ 工作项用时                                                │
│  等接口联调      累计 04:02:10      计时中        [删除]  │
│  写季度复盘      累计 01:28:33      已暂停        [删除]  │
│  修构建脚本      累计 00:12:00      未开始        [删除]  │
└──────────────────────────────────────────────────────────┘
```

- 卡片排序 = 清单顺序（最近开始的在最上）；每条只控制自己。
- 时长显示：本次用时（大字，等宽数字）+ 累计用时（小字）；不显示"当前专注对象"概念。
- **空态**：`当前没有进行中的计时 —— 从上方选择工作项开始，或直接在 TODO 清单点击 ▶`；「工作项用时」列表照常显示。
- 原先的「计时对象下拉 + 大号单计时数字」区块被列表取代，下拉仅作为"新增一项计时"的入口。

### 5.2 TODO 行状态（多计时并存）

```
[✓] 等接口联调   已计时 00:42:10  (计时中)   [⏸] [⏹]
[✓] 写季度复盘   已计时 00:30:23  (已暂停)   [▶] [⏹]
[✓] 修构建脚本   累计 00:12:00    (未开始)   [▶]
```

- 每行状态只来自**本行** `timingStatus`，不再有"当前有其它工作项正在计时"的提示。
- 顶部（或最上方的计时项）不再唯一高亮；所有 running 行都用同一种左侧强调色。

### 范围外（不做）

不改番茄钟任何逻辑（`PomodoroEngine`、提醒、推送）；不引入数据库/后端，仍是本地 JSON（electron-store）；不做工时手动修正与计时冲突自动拆分。
